| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 单次 Agent 调用 | ~10000 tokens | **~1500 tokens**（-85%） |
| System Prompt | 800 tokens | 500 tokens（-36%） |
| Preload 数据 | 4000（完整JSON） | 400（摘要）（-90%） |
| 历史案例 | 2000（全部） | 300（top-3）（-85%） |

---

## 设计原则

1. **每个 token 都要有产出目的** — 不能直接帮助 Agent 回答检查点→删
2. **压缩优于搬运** — 不是把数据搬到 prompt，是转换成 Agent 可直接消费的格式
3. **只传下游需要的** — 上游推理过程是上游的私有上下文，下游只需要结论
4. **高频预加载，低频按需取** — context window 是稀缺资源，按 ROI 分配
5. **设计时做，运行时少做** — 设计阶段控制好上下文结构，运行时不需要复杂动态截断

## 关键概念

- [[预加载]] — `preload_baseline_context`，并行拉取→摘要注入，消除 ReAct 轮次
- [[字段级压缩]] — 18 字段→6 关键字段（investigative_method 检查清单 = 唯一依据）
- [[检索式压缩]] — Episodic Memory top-3，用相关性排序做压缩
- [[生成式压缩]] — LLM 摘要对话历史/冗长工具返回（最后手段）
- [[Context Rot]] — 健忘：关键数字精度丢失、Lost in the Middle、早期证据被淹没
- [[Context Anxiety]] — 焦虑：反复确认、过度保守、生成冗长
- [[Prompt 精简]] — 36% 精简：去掉"调工具指南"改为"分析清单"

## 抗幻觉优先级

```
P0（不做系统基本不可用）:
  1. 工具数据锚定 — Agent 分析基于工具返回，不依赖训练记忆
  2. 结构化输出 — JSON Schema 约束 + temperature=0.1

P1（显著降危害）:
  3. 交叉验证 — 三个独立 Agent 互相不看到对方推理
  4. Guardrails — "NEVER say this is fraud"
  5. 预加载消除凭空回忆 — 数据在 prompt 里，不需要"回忆"

P2（锦上添花）:
  6. 来源引用 — key_evidence 标注来源工具
  7. 自检（Chain-of-Verification）— 事后验证事实一致性
  8. 置信度评分 — 每个发现标 confidence
```

---

## Prompt 调优优先级

```
1. Output Format 约束（最优先，改后立即见效）
2. 分析框架（改后需回归测试）
3. Few-shot Examples（最难 case 反复失败时加）
4. 措辞微调（最后手段，一次只改一个词）
```

---

## 关键概念

- [[数据锚定]] — 最有效的抗幻觉方法。Agent 只看工具返回的真实数据
- [[结构化输出]] — JSON Schema 约束，比自然语言更易验证
- [[Guardrails]] — System Prompt 的安全指令，"NEVER say this is fraud"
- [[Attention Dilution]] — Prompt 越长→每条规则被遵循的概率越低
- [[Few-shot Examples]] — "仿例子"比"理解定义"对 LLM 引导效果更好
- [[幻觉率]] — 事实陈述中不被工具数据支持的比例（应 < 5%）
- [[系统性幻觉]] — 三个 Agent 同时产生相同幻觉（共同源头导致），交叉验证防不住

## 记忆架构

```
工作记忆（Agent messages, ~1500 tokens）
    │ 调查完成
    ▼
情景记忆（ChromaDB, 数百-数千案例）
    │ 跨案例模式出现（同地址≥5次高风险）
    ▼

    │ 调查启动
    ▼

```

## 关键概念

- [[情景记忆]] — Episodic Memory，历史案例检索（ChromaDB top-3）
- [[语义记忆]] — Risk Registry，提炼后的风险模式/规则（JSON + ChromaDB 三维嵌入）
- [[模式生命周期]] — 语义记忆不是只增不减，有过期机制（6 个月无新案例→置信度衰减）

## 关键概念

- [[Hit Rate]] — Recall@K，12 条文档小向量库用 Hit Rate 不用 MRR
- [[Faithfulness]] — 报告中的事实是否被工具返回数据支持（反幻觉核心指标）
- [[LLM-as-Judge]] — 三个偏差需校正：位置偏差、长度偏差、自我增强偏差
- [[bootstrap test]] — Agent 非确定性要求统计检验验证 F1 提升
- [[per-type detection rate]] — takeover/sleeping/cashout 各自 F1，定位瓶颈
- [[逐改进对照实验]] — 8 轮 RAG 改进，每轮只变一个变量独立测量

## 新增功能点的通用面试话术（背这个，一鱼多吃）

> 「这个项目演进分五阶段：先把单 Agent 跑通（手写 ReAct），再上多 Agent 编排（LangGraph 10 节点），然后补权限（RBAC + HITL），接着做可靠性闭环（重试→自愈→熔断→幂等→告警），最后工程化落地（CLI 产品 + Redis/Milvus 可选后端 + 423 个离线测试 + 47 条评测）。**每层都是被真实问题逼出来的，不是堆功能**——比如熔断是因为 LLM 连续失败时重试=烧钱，幂等是因为重试/重规划会让写工具执行两次。」

## 新增踩坑故事（工程经验证明，面试最加分）

| 坑 | 一句话讲法 |
|---|---|
| `hash()` 跨进程随机化 → 样例库无限堆积 | 改 hashlib 稳定 ID，upsert 真去重 |
| Milvus URI 文件路径放环境变量 → 导入崩溃 | 本地路径只走构造参数，环境变量只放集群地址 |
| 拆分 orchestrator 后测试 monkeypatch 失效 | patch 改到代码实际所在模块 |
| configurable pyright 报错 | ConfigurablePayload TypedDict + agent_config() |
| RedisSaver 只能在 DB 0 建索引 | checkpoint 用 DB 0 + 独立 key 前缀 |
| 样例库脏数据污染 few-shot | 敏感列审计：薪资/手机/账户 SQL 不回流 |

> 面试官提醒：这 6 个坑是「真实工程经验」的证据，比任何功能点都值钱——它们证明你不是只会调 API，而是踩过坑、修过 bug。优先背。

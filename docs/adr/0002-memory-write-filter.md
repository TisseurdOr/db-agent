# 记忆写入必须过滤元问题，不能无脑 remember

无过滤写入会导致元问题（"上一个问题是什么""刚才查了什么"）污染向量库。因为这些查询的答案包含"之前的业务问答"——下一轮向量检索时，元问答可能排在真实业务记忆前面（相似度更高），模型读到后会将"上一次回答"误当作"当前上下文"。形成循环：错答 → 写入 → 被召回 → 再错答。

**Considered Options**

- **无脑写入**：所有 Q&A 都写 ChromaDB。简单但有自污染风险——元问答占向量检索 top_k 位置，挤掉真正的业务记忆。
- **memory_controller 分层过滤**：`should_remember()` 拦截元问题不写入；`is_meta_memory()` 在注入时二次过滤已污染的旧数据。元问题走 `list_recent(limit=20)` 时间倒序而非向量召回——因为语义检索对"刚才问了什么"必然失败。

**Consequences**

- 4 种记忆路由策略：闲聊跳过、元问题时间倒序、正常查询向量召回、元问答不写入。
- 代价：需要维护记忆路由规则，新增 query 类型可能漏过滤。但相比向量库污染后的清理成本（需全量 re-embed），这个代价可接受。

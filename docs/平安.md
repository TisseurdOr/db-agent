Prompt Caching 99.5%（简历数字，面试官一定追），三问：

1. 这个 99.5% 是怎么算出来的？分子分母分别是什么？
2. 它是总成本降了 99.5%，还是某个单项降了 99.5%？为什么这个区分在面试里很重要？
3. 你用什么机制实现的？它在什么条件下才真正生效（不是每轮都省）？
   "Prompt 缓存我是这么接的：把 system prompt 和工具描述稳定放在请求前缀，服务端命中缓存后，这部分输入 token 按 cache hit 价计费——cache hit 大概是 miss 的 1/100，所以 prompt 输入成本降了约 99%。缓存本身是服务商特性，我负责的是 prompt 结构优化、保证前缀逐字节一致让命中率最大化；
4. 另外我自己写的是 Router LRU，缓存路由决策结果，省的是每次路由那次 LLM 调用。具体我 demo 跑在 DeepSeek 上，它叫 context caching，固定前缀自动命中。"

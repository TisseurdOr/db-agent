白板手绘三步法（面试时照着画）

  1. 第一步画主干：用户 → Router（写"三级：规则/缓存/LLM"）→ 6 个 Agent 盒子 → Analysis → Reflection → 回答。边画边说："plan→execute→synthesize 标准流程"。
  2. 第二步画安全线：用虚线下挂一条贯穿的线："5 角色 RBAC + 表级/行级隔离 + 敏感查询 HITL 人工审批"——强调"Tool 层硬拦截，不是只靠 prompt"。
  3. 第三步补记忆和观测：右上角画"ChromaDB 长期记忆 + 自学习回流"，右下角画"JSONL + Opik 双写"。

每层面试要点（一句话）

  • Router："简单意图不烧 token——硬规则和缓存都是确定性的，只有兜底才调 LLM。"
  • 6 个 Agent："每个 Agent 是 prompt + tools + handlers 打包，执行循环和工具完全解耦，加工具不动循环。"
  • Confidence Gate："SQL 生成后不直接执行，LLM 按 6 项标准自评，低于阈值暂停人工确认。"
  • Reflection："Self-Refine 模式：自审完整性/真实性/可用性，不合格退回重写，最多 2 次——用 token 换质量。"
  • 安全线："双层生效：System Prompt 软约束 + Tool 层硬拦截；权限存数据库，改表即生效。"
  • 记忆："短期滑动窗口 + 摘要压缩；长期 ChromaDB 向量召回；成功 SQL 过质量门回流 few-shot，系统越用越准。"
  • 观测："本地 JSONL 审计（SQL 参数脱敏）+ Opik 执行树双写；成本按模型价格核算。"

主动自曝三件事（防被戳穿）

  • HBase/Hive 是本地模拟器：API 对齐、接口可替换，demo 不需要真集群——主动说，别等问。
  • 行级隔离是 SQL 改写：不解析完整 AST，生产应落数据库原生 RLS——先自曝再给演进方向。
  • 护栏是正则：定位成"零成本第一道闸"，真正兜底是 Tool 层白名单 + HITL 的纵深防御。

# db-agent 存储问题全解（面试 Q&A）

> 三问三答：**要保存什么 → 怎么存、存哪 → 为什么这么选**。
> 核心原则：**数据性质决定存储** + **可替换 + 降级**。

## 二、怎么存 + 存哪（6 种存储介质）

| 介质 | 存什么 | 存哪 | 写入路径 |
|---|---|---|---|
| **SQLite** | 业务/权限/记忆/反馈/模板/checkpoint 兜底/监控 | `db/demo.db`、`db/metric_registry.db`、`db/agent_state.db`、`monitor.db` | `sqlite3.connect()`：seed / run_query / save_to_memory / feedback / AsyncSqliteSaver |
| **Redis** | checkpoint（多 Agent 状态）、Web 会话 | `:6380/0` key `checkpoint_write:*`、`dbagent:session:*` | AsyncRedisSaver（每节点后）；sessions.py `rpush` + TTL |
| **向量库** | 长期记忆 / SQL 样例 / Schema 索引 | `harness/memory/chroma_db/`（或 `milvus_lite.db`/集群） | VectorMemory.remember / record_sql_example / build_index |
| **文件** | 日志、trace、评测基线 | `logs/db-agent.log`、`logs/traces/*.jsonl`、`logs/eval_baseline.json` | logging.FileHandler / TraceContext.save() / regression.save_baseline |
| **内存** | 摘要/指标/熔断/幂等/runner | 进程内 | ConversationManager / ops_metrics / CircuitBreaker / RunnerRegistry |
| **配置** | keys/参数 | `.env` | load_dotenv() |

**触发条件**：Redis 配 `REDIS_URL` + redis-stack 才启用，否则降级 SQLite/内存；向量 `VECTOR_DB=chroma|milvus` 切换。

## 三、为什么这么选（数据性质 → 存储）

| 数据性质 | 决定用 | 为什么 |
|---|---|---|
| 结构化、小、单机、要事务 | **SQLite** | 零运维、单文件、ACID；生产换 Postgres 有抽象（注释里写了"生产可换 PostgresSaver"） |
| 热状态、多实例共享、要 TTL | **Redis** | 多实例一致（状态外置）；TTL 防无限膨胀（375MB 教训）；KV 天然匹配 |
| 要语义检索 | **向量库** | embedding + ANN；Chroma 匹配规模，Milvus 备规模上来（双后端抽象） |
| 只追加、按天审计、要 grep | **文件** | JSONL 每行一个 trace、O(1) 追加、好 grep 好备份；审计日志不进库 |
| 会话内瞬态、跨进程无意义 | **内存** | 摘要/指标/熔断单实例够用（多实例外置是已知欠账） |
| 密钥 | **.env** | 12-factor，不入库、按环境注入、启动校验 |

**可替换 + 降级原则**：状态是"可再生资产"——checkpoint 有 SQLite/Redis 双后端、向量有 Chroma/Milvus 双后端、Redis 挂了自动降级，因为丢了顶多会话重来。

## 四、面试口径

> "我的存储选型原则是**数据性质决定存储**：结构化小数据用 SQLite，热状态用 Redis（TTL 防膨胀），语义检索用向量库，追加审计用文件，会话内瞬态用内存。同时坚持**可替换 + 降级**——checkpoint 有 SQLite/Redis 双后端、向量有 Chroma/Milvus 双后端、Redis 挂了自动降级，因为状态是可再生的。没有用大而全的东西，是因为每个选型都对应当前数据规模；规模变了，换的是后端，不是架构。"

> "要保存的东西分七层：业务库、模板库、编排状态（checkpoint）、Web 会话、向量三件套（记忆/样例/schema 索引）、可观测（日志/trace/基线/监控）、配置。会话内记忆是内存的，重启靠 checkpoint 恢复。"

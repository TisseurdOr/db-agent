## 一句话

系统不再「只出不进」：成功跑通的 SQL、以及用户 HITL 批准的 SQL，会自动写回样例库；下次相似问题命中 few-shot，越用越准。

## 数据流（改正后）

```
用户提问
  → get_sql_fewshot(query)          # 读：召回已验证 Q→SQL
  → SQL Agent
       → run_query 成功 → 记下 SQL   # 工具层捕获（主路径）
  → pop_last_successful_sql()
  → learn_from_success(q, result, sql=捕获的SQL)
       → 质量门 dry-run → Chroma sql_examples
       ↑
HITL 用户点 y 批准
  → learn_from_hitl(q, interrupt里的sql)   # 写：人工背书，source=hitl
```

| 路径 | 触发点 | source | SQL 来源 |
|------|--------|--------|---------|
| 自动回流 | `node_sql` 成功结束后 | `auto` | **`run_query` 成功路径**（`pop_last_successful_sql`）；文本提取仅作兜底 |
| HITL 回流 | `main.py` 用户批准后 | `hitl` | interrupt payload 里的 `sql` |
| 读路径 | SQL 节点执行前 | — | `get_sql_fewshot`（第 2 项） |

**节点开始时会先清空**上一轮残留的成功 SQL，避免 Agent 超时后误把探索性查询回流进样例库。

## 质量门（宁缺毋滥）

全部通过才写入：

1. `AUTO_LEARN_SQL` 未关闭（默认开）
2. 不是超时垃圾文本（`is_agent_timeout`）
3. 不是纯错误 JSON / 用户拒绝文案
4. 拿到完整 `SELECT`/`WITH`（优先工具层捕获；否则从回答里抽 markdown / 语句）
5. **该 SQL 必须能在真实 `demo.db` 上 dry-run 跑通**——半截答案、字段名仍错的绝不入库

自愈场景允许回答文本里留下 `no such column`（失败痕迹），只要最终捕获/抽出的 SQL 可执行就回流。

## 环境变量

```bash
AUTO_LEARN_SQL=1   # 设 0 / false 关闭自动回流（读路径 few-shot 不受影响）
# 写路径还需要 EMBEDDING_API_KEY；缺失时静默降级，不挡主流程
```

现场观察点：

| 日志 | 含义 |
|------|------|
| `📚 few-shot: 命中 N 条相似 SQL 样例` | 读路径生效 |
| `📥 自学习: 回流样例 [auto] …` | 自动写回成功（live 幕必须出现） |
| `📥 自学习: HITL 批准回流 …` | 人工批准写回 |
| 业务答对了但没有 `📥` | 旧 bug：只从自然语言抽 SQL——已改工具层捕获；若复现查 `pop_last_successful_sql` |
| 无写入、也无报错 | 质量门拦截，或未配 `EMBEDDING_API_KEY`（静默降级） |

## 踩坑改正（2026-08-06 现场）

**错误做法（已废弃）**：只从 SQL Agent 的自然语言回答里正则抽 `SELECT`。

**现象**：问「产品部有多少笔已完成订单」——查数正确（32）、few-shot 也命中了，但始终没有 `📥 自学习`。

**原因**：SQL Agent 习惯口头描述逻辑（「通过 `orders.dept_id = departments.id` 关联…」），**回答里不带完整 SELECT**。`extract_sql()` 返回 `None` → 质量门直接拒绝 → 闭环名存实亡。

**正确做法**：
1. `common/tools/query.py`：`run_query` **仅在执行成功时**写入 `_last_successful_sql`
2. `node_sql` 开始时 `pop` 清空残留；成功结束后再 `pop` 交给 `learn_from_success(..., sql=捕获值)`
3. 文本提取降为兜底；单测覆盖「成功捕获 / 报错不捕获」

**教训**：回流信号要取**工具执行事实**，不要赌模型在最终回答里复述 SQL。

详见 `docs/操作与排障/troubleshooting.md` 第 25 条。

## 面试 20 秒版

「few-shot 样例库不只靠种子数据——成功查询和 HITL 批准的 SQL 会自动回流。
SQL 从 `run_query` 成功路径捕获，不依赖模型是否把 SELECT 写进回答。
写之前过质量门，最硬的一道是在真实库上 dry-run；读失败、写失败都静默降级，挡不住主流程。」

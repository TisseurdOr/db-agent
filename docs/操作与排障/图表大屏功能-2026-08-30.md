# 图表大屏功能打通 — 2026-08-30

## 背景 / 问题

`render_chart`（Analysis Agent 的工具）能生成暗色主题 HTML 数据大屏，落在
`harness/charts/dashboard_*.html`。但文件生成了，**前端页面看不到**——页面上的图
是另一条路（`_auto_chart_from_sql_result` 从 SQL 结果纯规则推断的内联 echarts），
与 render_chart 的大屏 HTML 完全无关。

## 根因

`render_chart` 返回的 `dashboard_path` 是**文件系统绝对路径**（如
`/Users/.../harness/charts/dashboard_xxx.html`），前端既拿不到、也访问不了：

1. 路径在 Analysis Agent 内部工具调用里，`node_analysis` 没有把它单独提取到 state；
2. 就算拿到绝对路径，浏览器也只能通过 HTTP 访问，不能读本地文件。

## 方案

**Sidebar 加「Dashboard」tab + iframe 展示最近一次大屏 HTML。**

备选方案（已讨论、未采用）：
- 消息气泡内嵌 iframe —— 跟着消息走，但用户选了 Sidebar tab；
- 新标签打开 —— 改动最小，但要点击跳转；
- 内联 echarts 复用 —— 丢大屏的 KPI 卡片 / 暗色主题，与现有 ChartPanel 重复。

## 改动清单（8 处）

| 文件 | 改动 |
|---|---|
| `harness/tools/chart.py` | `render_chart` 记录最新大屏 URL，返回加 `url` 字段 |
| `server/endpoints/dashboard.py` | 新建 `GET /api/dashboard/latest`，内存指针丢了就回退扫 `charts/` 目录 |
| `server/main.py` | 注册 dashboard 路由 + `mount("/charts", StaticFiles(CHART_DIR))` |
| `frontend/src/components/Sidebar.tsx` | `MainTabId` + NAV 加 `dashboard` |
| `frontend/src/components/MainTabs.tsx` | `TAB_TITLE` 加 dashboard + 渲染 `<Dashboard />` |
| `frontend/src/components/Dashboard.tsx` | 新建：fetch `/api/dashboard/latest`，iframe 展示，10s 自动刷新 |
| `frontend/vite.config.ts` | dev 模式加 `/charts` 代理到 8000（否则 iframe 404） |
| `tests/test_server.py` | 加 `/api/dashboard/latest` + `render_chart` 更新 URL 两个测试 |

## 验证

- `pytest tests/test_server.py` → 20 passed
- `npx tsc -b` → 通过
- 端到端全链路 200：`/api/dashboard/latest` → `/charts/dashboard_20260829_085256.html`，
  `/charts` 静态文件返回 `text/html`

## 使用

打开 http://localhost:3001 → 左侧 **📈 Dashboard** tab → iframe 显示最近一次大屏。
以后每次让 Agent 分析数据生成新大屏，tab 会 10 秒自动刷出最新的。

## 关键设计点

- **磁盘回退**：`_latest_dashboard_url` 是进程内存变量，后端重启就丢；endpoint 在
  指针为空时扫 `charts/` 目录取最新文件，保证重启后历史大屏仍能显示。
- **dev / 生产双路径**：dev 模式 vite proxy `/charts` → 8000；生产模式前端 build 由
  后端 `mount("/charts")` 同源 serve，无需 proxy。
- **单机 demo 假设**：最新大屏是全局单指针，非 session 级；多用户需改成按 session 记录。

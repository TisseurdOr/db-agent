# AGENTS.md — 本 Vault 的 Agent 维护规则

> 目标：Agent 不只回答问题，还负责把知识库"维护"好：新增笔记补双链、同主题合并、更新主题 Index、新经验沉淀。
> 人负责提供背景、判断重要关系、确认最终结论；Agent 负责降低记录、检索和整理的成本。

## 目录约定

| 目录 | 放什么 | Agent 写入权限 |
|------|--------|----------------|
| `00-inbox/` | 待整理素材 | ✅ 可写 |
| `新手手册/` | 用户/Web/API/工具/新手 PPT | ⚠️ 改手册需人工确认 |
| `操作与排障/` | 排障、错误恢复、自学习、专题 | ⚠️ 同上 |
| `项目介绍/` | 产品介绍、复盘、工程机制 | ⚠️ 只读为主 |
| `面试/` · `面试/公司面经/` | 题库话术、公司专项 | ⚠️ 只读为主 |
| `简历与经历/` | 简历 STAR、经历/项目 PPT | ⚠️ 只读为主 |
| `其他项目/` | fin-agent / fraud-agent 等 | ⚠️ 只读为主 |
| `adr/` · `diagrams/` | 架构决策、图示 | ⚠️ 只读为主 |
| `30-沉淀/` | 正式结论（审核后） | ❌ 只读（人工发布） |
| `ai/drafts/` | 新经验草稿 | ✅ 可写 |
| `ai/indexes/` | 主题 Index | ⚠️ 对照变更 |
| `ai/logs/` | 维护日志 | ✅ 可写 |

> 分类索引见 [`README.md`](README.md)。新文件必须进对应类别目录，禁止再堆在 `docs/` 根下。

## 检索顺序（固定规则）

1. 先查 `新手手册/` / `操作与排障/` / `项目介绍/` 中与主题匹配的正式文档；
2. 再查 `ai/indexes/` 主题 Index（当前结论优先）；
3. 面试口径查 `面试/`；简历口径查 `简历与经历/`；
4. **冲突裁决**：知识库与代码/线上实现说法不一致时，**以代码和线上实现为准**，并在笔记中标注差异。

## 写入边界

- 只允许在 `00-inbox/`、`ai/drafts/`、`ai/logs/` 自由写；正式目录写入需人工授权。
- 每次修改后，必须同步：① 该笔记的反向链接/出链；② 所属主题 Index 的「更新日期 + 相关笔记」。
- 同一主题内容分散时，合并或互相链接，并标注「当前结论 / 历史结论」。

## 双链规范

- 新笔记必须链到所属主题 Index（找不到 Index 就先建）。
- 引用来源用 `[[wikilink]]` 指向原始笔记；附件保持正文引用路径可解析。
- 过期结论不删除，移到「历史结论」并写明替代结论。

## 并发写入（多 Agent 共享 Vault 时）

- 规则：**先读取 → 修改 → 提交**。
- 若写入接口支持版本校验（MCP `vault_patch` 的 `ifMatch=version`）：提交时带上读取到的 version；
  服务端返回 412 说明别人已改，**重新读取最新内容再提交**，不要覆盖他人修改。
- 这是整文件粒度乐观并发：宁可冲突后重读，不可静默覆盖。

## 沉淀闭环（新经验怎么进正式知识）

1. 任务产生可复用结论 → 写入 `ai/drafts/`（带来源链接）；
2. 人工审核（谁写的、是否可复用、口径是否对）→ 移动到对应类别目录或 `30-沉淀/`；
3. 更新主题 Index；
4. 后续相似任务必须先在 Index/领域知识里检索复用。

## 度量（写进 ai/logs）

- 每次检索任务记录：命中/误命中/漏命中、定位耗时、调用工具序列（可对齐 db-agent 的 Trace/JSONL）。
- 每次任务结束记录：最终结论是否引用了已有笔记（知识复用率）。
- 每次沉淀记录：写回→审核→发布→后续复用是否完成（沉淀闭环完成率）。
